# 形成能预测的验证器循环：LLM 特征、记忆与对照

状态：截至 2026-11-01。H2–H4 实验已完成，H5 未开始。

## 研究问题

LLM 能否在同样标签数下，为形成能预测写出比普通描述符更好的特征？循环（每轮根据验证误差改写特征）和记忆（每轮附带历史记录）是否带来额外收益？

## 主要结果（合成 TEST，按题的平均绝对误差，单位 eV/atom，越小越好）

| 方法 | 标签数 | 平均误差 | 95% 范围 |
|---|---|---|---|
| 一次性 LLM 特征（O） | 2000 | 0.2139 | 0.2003 到 0.2287 |
| 循环 LLM 特征（L0） | 2000 | 0.2108 | 0.1989 到 0.2233 |
| 循环加记忆（L1） | 2000 | 0.2086 | 0.1965 到 0.2222 |
| 只用 Magpie | 2000 | 0.2335 | 0.2169 到 0.2526 |
| 只用 Magpie | 5000 | 0.2101 | 0.1948 到 0.2269 |
| CGCNN | 2000 | 0.1665 | 0.1572 到 0.1754 |
| CGCNN | 5000 | 0.1137 | 0.1072 到 0.1203 |

关键配对比较（差值，95% 范围）：

- 循环减一次性（L0 减 O）：−0.003，范围 −0.011 到 +0.004，包含 0。
- 加记忆减循环（L1 减 L0）：−0.002，范围 −0.009 到 +0.004，包含 0。
- 同样 2000 标签，L1 减 Magpie：−0.025，范围 −0.040 到 −0.012，显著。
- L1 减全部 5000 标签的 Magpie：−0.0015，范围 −0.014 到 +0.010，基本持平。
- L1 减 CGCNN（2000 标签）：+0.042，范围 +0.032 到 +0.052，LLM 特征明显更差。

迁移到真实 DFT 数据（HOLDOUT 2000，按题的平均误差）：Magpie 0.2221，一次性 O 0.1989，循环 L0 0.1913，循环加记忆 L1 0.1873。L1 减 Magpie 为 −0.035，范围 −0.044 到 −0.026，显著。

结论：同样标签数下，LLM 特征优于普通描述符，并能迁移到真实数据。但循环和记忆本身没有可靠增益，循环的收益大致相当于多给 3000 个标签。直接学习结构的 CGCNN 远好于 LLM 特征。

## 目录

- `code/H4_src/`、`code/H4_tests/`：H4 阶段的全部实验代码和测试（循环、记忆、统计、沙箱执行、LLM 调用的封装）。
- `docs/`：H2 数据说明、H3 结果说明、H4 阶段 4.2、4.3、4.4 的完整报告。
- `predictions/H4_predictions_TEST.csv`：H4 三个阶段在合成 TEST 上的预测（9000 行）。
- `data/H2/`：H2 数据生成的全部文件，包括合成数据（POOL 5000、TEST 1000）和真实数据（DFT 与 CHGNet 标签）的 `*_private.json.gz` 文件。
- `data/H4/`：H4 工作目录，包括每轮的 LLM 请求与回复记录（`llm_calls.jsonl`、`requests/`）、特征代码、统计输出、报告，以及中间缓存。
- `data/H4_feature_loop/`：H4 对外公开目录的原始文件（预测、指标、运行日志、配置）。
- `data/README.md`：数据目录的逐项索引，说明每个文件和子目录的内容。
- `docs/PROTOCOL_REVISIONS.md`：全部协议修订、中途改动和偏差的记录，每条写明时间、原因和对结论的影响。

## 数据政策

以下内容都已公开，包括：

- POOL、TEST、HOLDOUT 的标签。
- LLM 的 prompt 与回复记录。prompt 中嵌入了带标签的示例。

注意：本研究测的是 LLM 有没有记忆这些数据。这些标签现在公开，之后的 LLM 很可能在训练时见过它们，之后用这批数据做的记忆测试不再是盲测。之后做记忆测试需要新的数据。

## 复现

复现需要：

- Python，CHGNet 0.3.0，matminer（Magpie 特征）。
- Matbench mp_e_form（真实 DFT 形成能来源）：<https://figshare.com/articles/dataset/mp_e_form/9755432>
- Codex CLI 与 gpt-6.1-sol 的访问权限：<https://github.com/openai/codex>

**路径要求。** H4 的代码用 `Path(__file__).resolve().parents[4]` 定位项目根目录，要求代码位于原始工作目录的层次中，即 `<ROOT>\work\h-data\H4\src`。`code/H4_src` 和 `code/H4_tests` 直接放在本仓库里运行时，这个路径不对，会找不到数据。要复现，有两种方法：

1. 把 `data/` 下的内容放回 `<ROOT>\work\h-data\` 下，对应 H2 和 H4 的目录，然后从原始位置运行代码。
2. 修改每个 `.py` 文件中的 `ROOT` 定义，指向本仓库的根目录。

H2 的生成与评估脚本在 `data/H2/protocol_revision1_prior/`、`protocol_revision2_prior/` 和 `resource_revision0/` 中，文件名以 `h2_` 和 `p1_` 开头。

如果只想核对结果，不需要运行代码：直接看 `docs/` 中的报告和 `predictions/` 中的预测即可。
